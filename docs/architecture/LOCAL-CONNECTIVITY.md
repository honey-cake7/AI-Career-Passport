# Local connection recovery

Date: 2026-11-18. AI-assisted troubleshooting on `feat/career-passport-v2`; production settings and databases were not migrated.

Two Vite projects were using port 5173 on different addresses: AlgoLens on IPv4 and Career Passport on IPv6. The suggested explicit IPv6 browser URL loaded Career Passport, but it did not match the backend's allowed `http://localhost:5173` origin. The browser consequently hid the sign-in response as a connection failure. A raw HTTP health check alone did not catch that CORS failure.

Give Career Passport a unique local port. `frontend/.env.local` can set `VITE_DEV_PORT=5174`; set backend `FRONTEND_URL=http://localhost:5174` and restart both. A configured dev port binds localhost and is strict, preventing silent port drift into another browser origin. Open `http://localhost:5174`, not an IP literal. The default example still uses 5173. No wildcard CORS or extra production origin was added, and the other project was left running.

On restart, the backend's existing Atlas URI failed separately. A credential-safe probe showed `ECONNREFUSED` for the system DNS resolver's Atlas SRV lookup. The same lookup succeeded using alternate resolvers, and a process-only DNS override then connected and completed an authenticated Atlas ping. The URI/credentials and existing accounts/data were retained; a local MongoDB service does not control this Atlas connection. No OS/network adapter DNS setting was changed.

Optional backend `DNS_SERVERS` applies one to three validated IP addresses via Node's `dns.setServers` before database connection. Unset/blank preserves platform defaults. Use network-approved resolvers; this setting affects Node resolver operations such as SRV/TXT, not every OS-backed lookup or other application. The local ignored configuration uses the verified alternative; environment examples leave it blank. Invalid configuration stops startup before modifying the resolver. This does not bypass Atlas authentication, TLS or network access restrictions, and does not fix unrelated Atlas outages.

Verification: the ordinary backend dev command connected to Atlas, and the ordinary frontend dev command served Career Passport on 5174. An isolated Chromium browser exercised the actual sign-in form with deliberately invalid synthetic credentials: it received the expected 401 validation message, rather than a network/CORS error, and could read the backend health response. It created no account and changed no resume. Backend build and test typecheck passed; 102 backend unit/HTTP tests and 60 backend integration tests passed. Frontend production build and lint with warnings denied passed. The unit suite includes three resolver configuration checks. This verifies connectivity and existing regression coverage; it does not claim to have signed into the owner's account or tested live AI quality.

Normal local startup remains `npm.cmd run dev` in each of `backend` and `frontend`. If changing ports later, keep the browser URL and backend allowed origin identical and restart both. If the network's DNS is repaired, remove the optional resolver override and restart the backend. Local `.env` files are ignored and must not be committed. Same development-branch commit/push and secret/diff checks apply; no main merge or deployment is authorized by this fix.
